## 📋 工作流概述

本工作流用于从 ERP 系统导出的作废订单 Excel 文件中批量作废订单，包括：
1. 更新 orders 表的订单状态和备注
2. 更新 order_shipment 表的运单状态为 cancelled
3. 输出运单号列表，提醒用户到 carrier 平台取消运单

---

## 🎯 输入要求

### **Excel 文件格式**
- **文件类型**: `.xlsx`
- **必需列** (4个):
  - `订单编号` - 订单的唯一标识符 (transaction_id)
  - `订单状态` - 中文状态（如"已作废"）
  - `订单备注` - 作废原因说明
  - `货运单号` - 关联的运单号

### **字段映射**
| Excel 列名 | 数据库字段 | 转换规则 |
|-----------|-----------|----------|
| 订单编号 | transaction_id | 字符串，trim() |
| 订单状态 | order_status | 中文→英文枚举映射 |
| 订单备注 | remarks | 中文→英文自动翻译 |
| 货运单号 | tracking_no | 字符串，trim()（仅用于输出提醒） |

### **订单状态映射**
使用 `lib/admin/column-maps/order-import-config.js` 中的映射：
- "已作废" → "cancelled"

## 🔄 工作流程

### **步骤1: 读取并验证 Excel 文件**
- 检查文件是否存在
- 验证必需列是否完整
- 统计记录数

### **步骤2: 解析数据**
- 提取订单编号、订单状态、订单备注、货运单号
- 转换订单状态（中文→英文）
- **翻译订单备注（中文→英文）**

### **步骤3: 检查订单存在性**
- 批量查询数据库中已存在的订单
- 分为：已存在订单、不存在订单

### **步骤4: 更新 orders 表**
- 批量更新 order_status 为 "cancelled"
- **翻译 remarks 字段（中文→英文）**
- 收集所有运单号

### **步骤5: 更新 order_shipment 表**
- 根据运单号更新 shipment_status 为 "cancelled"
- 去重处理（同一运单号只更新一次）

### **步骤6: 更新 order_billing 表**
- 将所有作废订单的 freight_est_cny 设为 0
- 确保作废订单不产生预估运费

### **步骤7: 生成执行报告**
- 统计成功/失败数量
- 列出不存在的订单
- **输出运单号列表**，提醒用户到 carrier 平台取消

## ⚠️ 错误处理策略

### **跳过并继续**
- ❌ 订单不存在于数据库 → 跳过，记录到失败列表，继续处理其他订单
- ❌ 单个订单更新失败 → 记录错误，继续处理其他订单
- ❌ 运单号不存在于 order_shipment 表 → 记录错误，继续处理其他运单

### **立即中断**
- ❌ Excel 文件不存在
- ❌ Excel 缺少必需列
- ❌ Excel 文件为空

### **退出码**
- **0**: 所有订单都成功更新
- **1**: 存在不存在的订单或更新失败的订单

## 🔧 技术细节

### **备注翻译功能**

#### **本地翻译策略**
脚本使用内置的中文到英文映射表进行翻译，无需外部 API。

**翻译流程：**
1. 检测文本是否为纯英文（ASCII），如果是则直接返回
2. 使用预定义的映射表进行逐词替换
3. 按长度降序匹配，优先翻译长词（如“平台退款”优先于“退款”）
4. 如果仍有未映射的中文字符，显示警告并保留部分翻译结果

#### **常见备注映射表**
```javascript
const translationMap = {

  '平台取消': 'Platform cancellation',

  '库存不足': 'Insufficient inventory',
  '地址错误': 'Incorrect address',
  '重复下单': 'Duplicate order',
```

#### **翻译示例**

### **订单状态映射**
- Excel 中的"已作废"会自动映射为数据库枚举值 "cancelled"
- 如果 Excel 中已经是英文枚举值，会直接使用

### **运单号去重**
- 使用 Set 数据结构自动去重
- 确保每个运单号只更新一次

### **更新顺序**
1. 先更新 orders 表（订单状态和备注）
2. 再更新 order_shipment 表（运单状态）
3. 然后更新 order_billing 表（freight_est_cny = 0）
4. 最后输出运单号列表

## 📝 注意事项

### **运单取消提醒**
- ⚠️ **重要**: 脚本只会更新数据库中的运单状态
- 💡 **必须手动操作**: 需要到各物流商平台（燕文、云途、HH Express等）实际取消运单
- 💰 **避免费用**: 不及时取消可能产生运费

### **订单备注可选**
- 如果 Excel 中订单备注为空，只更新 order_status
- 不会将 remarks 设置为 NULL

### **订单不存在处理**
- 不会中断流程
- 会在报告中明确列出所有不存在的订单
- 退出码为 1，便于自动化脚本检测
