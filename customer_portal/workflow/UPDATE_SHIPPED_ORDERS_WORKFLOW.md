## 📋 工作流概述

本工作流用于从 ERP 系统导出的已发货订单 Excel 文件中批量更新数据库中的订单状态和发货时间。

### **核心功能**
1. 读取并验证 Excel 文件格式
2. 检查订单是否存在于数据库
3. 批量更新 order_status 和 dispatch_date
4. 报告不存在的订单（不中断流程）

---

## 🎯 输入要求

### **Excel 文件格式**
- **文件类型**: `.xlsx`
- **必需列** (3个):
  - `订单编号` - 订单的唯一标识符 (transaction_id)
  - `订单状态` - 中文状态（如"已发货"）
  - `发货时间` - 发货日期时间

### **字段映射**
| Excel 列名 | 数据库字段 | 转换规则 |
|-----------|-----------|---------|
| 订单编号 | transaction_id | 字符串，trim() |
| 订单状态 | order_status | 中文→英文枚举映射 |
| 发货时间 | dispatch_date | YYYY-MM-DD HH:mm:ss |

### **订单状态映射**
使用 `lib/admin/column-maps/order-import-config.js` 中的映射：
- "已发货" → "shipped"
- "配货中" → "processed"
- "待处理" → "received"
- "已作废" → "cancelled"

## 🔄 工作流程

### **步骤1: 读取并验证 Excel 文件**
- 检查文件是否存在
- 验证必需列是否完整
- 统计记录数

### **步骤2: 解析数据**
- 提取订单编号、订单状态、发货时间
- 转换订单状态（中文→英文）
- 转换发货时间格式（支持 Excel 日期序列号和字符串）

### **步骤3: 检查订单存在性**
- 批量查询数据库中已存在的订单
- 分为：已存在订单、不存在订单

### **步骤4: 更新已存在订单**
- 批量更新 order_status
- 有条件更新 dispatch_date（仅当有值时）
- 分批处理（每批50个订单）

### **步骤5: 生成执行报告**
- 统计成功/失败数量
- 列出不存在的订单
- 列出更新失败的订单

## ⚠️ 错误处理策略

### **跳过并继续**
- ❌ 订单不存在于数据库 → 跳过，记录到失败列表，继续处理其他订单
- ❌ 单个订单更新失败 → 记录错误，继续处理其他订单

### **立即中断**
- ❌ Excel 文件不存在
- ❌ Excel 缺少必需列
- ❌ Excel 文件为空

### **退出码**
- **0**: 所有订单都成功更新
- **1**: 存在不存在的订单或更新失败的订单

## 🔧 技术细节

### **日期格式转换**
支持两种格式：
1. **Excel 日期序列号**（数字类型）
   ```javascript
   const ms = Math.round((excelDate - 25569) * 86400 * 1000);
   const dateStr = new Date(ms).toISOString().replace('T', ' ').slice(0, 19);
   ```

2. **字符串格式**
   ```javascript
   const dateStr = String(dateValue).trim().replace(/\//g, '-');
   ```

### **批量更新策略**
- 分批大小：50个订单/批
- 逐条更新（确保每个订单的更新状态可追踪）
- 错误隔离（单个订单失败不影响其他订单）

## 📝 注意事项

### **订单状态映射**
- Excel 中的"已发货"会自动映射为数据库枚举值 "shipped"
- 如果 Excel 中已经是英文枚举值，会直接使用

### **发货时间可选**
- 如果 Excel 中发货时间为空，只更新 order_status
- 不会将 dispatch_date 设置为 NULL

### **订单不存在处理**
- 不会中断流程
- 会在报告中明确列出所有不存在的订单
- 退出码为 1，便于自动化脚本检测
